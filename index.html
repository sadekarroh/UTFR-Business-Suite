Email Campaign
Compose, personalize, and send mass emails
Sending a campaign Four tabs, in order
  1. Compose — write the subject and body. Put a column name in { } wherever each person's own details should go.
  2. Recipients — upload a spreadsheet, or pull straight from Sponsors or Contacts. Click rows to include or exclude them.
  3. Preview — see the first three emails exactly as they'll arrive, with the real names filled in. Red chips mean a { } matched nothing.
  4. Send — add the Gmail address and app password, send one to yourself first, then send the lot.
Merge fields — the { } bit

Anything you wrap in curly braces is swapped for that column from your spreadsheet, one person at a time. Say your sheet looks like this:

First nameCompany NameEmailDeal Size
DanaAventry Medicaldana@aventry.com$5,000
SamLitenssam@litens.com$10,000

Write this:

You type
Hi {First name},

We'd love to have {Company Name} on the car this season. Our {Deal Size} tier includes livery placement and a pit garage visit.
↓ sends as two separate emails ↓
Dana gets
Hi Dana,

We'd love to have Aventry Medical on the car this season. Our $5,000 tier includes livery placement and a pit garage visit.
Sam gets
Hi Sam,

We'd love to have Litens on the car this season. Our $10,000 tier includes livery placement and a pit garage visit.

Capitals, spaces and underscores don't matter. A column headed First name is found by {First name}, {first_name} and {FIRSTNAME} alike. It works in the subject line too.

When a cell is empty

Add a fallback after a vertical bar: Hi {First name|there}, sends “Hi there,” rather than “Hi ,”.

If you misspell a column

Nothing is guessed. {Compny} goes out exactly like that, braces and all. Preview flags it in red and the Send tab warns you before you commit — which is the whole reason to look at Preview first.

How fast they go out

Spread out is the default and the one to use. Emails leave one at a time, about 5 minutes apart — the exact gap is random, drawn from a bell curve with a standard deviation of 1.6 minutes, so roughly two thirds of the gaps fall between 3.4 and 6.6 minutes and no two campaigns have the same rhythm.

That matters because a hundred identical messages leaving in the same second is the clearest signal of bulk mail there is. Spacing them irregularly looks like somebody working down a list, which is what it actually is.

It runs without you

In the production build the schedule is written to a queue table in PostgreSQL, and a database job sends whatever is due once a minute. Close the tab, shut the laptop, go home — it carries on. Progress shows in the Queue below the Send button, and Cancel what's waiting stops anything that hasn't gone yet. In this demo the queue is built and shown but nothing is sent.

Only during working hours

Sending pauses outside weekdays, 8am to 6pm and picks up the next morning, so nothing lands in a sponsor's inbox at 3am. A 50-person campaign takes about four hours; 165 people spills across two days.

All at once is there for small, urgent sends — a handful of people who need it now. It fires from this page, so the tab has to stay open.

The sending account

This is the demo build, so there is no sending account and nothing leaves your browser. Everything else on this page is live — write a template, pick recipients, preview the personalised copy, and press Send to watch the scheduler lay out the queue.

For context, here is how the real one works. Google will not let an app use an account password, so the team generates a 16-character Gmail app password and the suite hands it to a server-side function that speaks SMTP. Nothing is installed and no terminal is involved. Because a spread-out campaign keeps running after the page is closed, the password is also stored server-side for the scheduler — in a table with INSERT and UPDATE policies but deliberately no SELECT policy, so the browser can put a password in and can never read one back out. Revoking the app password in Google kills it everywhere at once.

Worth knowing
  • Always send one to yourself first. The button next to Send does exactly that, using the first recipient's real details. Links, spacing and merge fields all look different in an inbox than in a preview.
  • Gmail's daily ceiling is about 500 messages on a personal account and 2,000 on Workspace. Past it Gmail starts refusing, and those show up in the failure list.
  • Rows without a usable email are skipped automatically and the count on the Send button reflects that, so it's never a surprise.
  • Nothing can be unsent. There's a confirmation naming the number of people and the address it's coming from — read it.
  • Anything that bounces is listed with Gmail's own reason, so you can fix those addresses and re-send to just them.
